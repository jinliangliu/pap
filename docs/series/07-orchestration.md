# 多智能体平台实战（七）：编排，把流程存成数据

## 1. Why：为什么需要第二张图

第 2 篇画的七节点图是**对话图**：一问一答，形状固定。它解决「一次请求怎么处理」。

但真实业务里有一类需求它表达不了：**A 之后一定要跑 B，而且要跑五个步骤，中间还要查台账。**

这种流程有两个特征：

- **顺序是确定的**，不需要模型每轮重新决定下一步；
- **步骤是可枚举的**，可以画出来给人看。

让对话图去跑这类任务，会有两个后果：每一跳都要花一次模型调用（贵、慢、还会跳错）；
流程改一次就要改代码（发版）。

所以有了第二张图：**编排图**。它是配置，不是代码。

---

## 2. What：图是配置，解释器是代码

一张编排图在结构上只有四样东西：

| 元素 | 作用 | 约束 |
|---|---|---|
| `entry` | 从哪个节点开始 | 必须存在 |
| `nodes` | 节点集合，每个有 agent、task、输入输出 | 必须有后继或标记终点 |
| `edges` | 普通边与条件分支 | 指向的节点必须存在 |
| `max_nodes` | 单次运行节点预算 | 必须 ≥ 最长路径 |

节点本身不写代码。它只声明：用哪个 Agent、任务模板是什么、输入从哪来、
输出落在哪个变量上。

```yaml
entry: collect
nodes:
  - id: collect
    agent: ops
    task: "查询 {{site}} 近 24 小时的压力数据"
    emit: { metrics: "$.result" }
    next: [{ to: judge }]
  - id: judge
    agent: ops
    task: "对照 {{metrics}} 判断是否超限"
    emit: { level: "$.level" }
    next: [{ to: alert, when: "level", equals: "high" },
           { to: report }]
```

解释器按图跑，每一步只是一次 Agent 调用。**加一个步骤是改配置，不是发版。**

---

## 3. How：编译期就要挡住六类错

运行到那一跳才发现问题，代价是一次跑了一半的任务，加上一堆半成品数据。

所以图在保存时就编译，编译时逐项校验：

| 校验 | 挡的问题 | 错误码 |
|---|---|---|
| 每个非终点节点都有后继 | 执行到一半卡死 | `WORKFLOW_NO_EDGE` |
| 边指向的节点存在 | 悬空边，跑起来才 500 | `WORKFLOW_DANGLING_EDGE` |
| 从入口可达所有节点 | 配了却永远不跑，图看起来比实际能做得多 | `WORKFLOW_UNREACHABLE_NODE` |
| `max_nodes` ≥ 最长路径 | 某条路径跑到一半被截断 | `WORKFLOW_NODE_BUDGET_TOO_SMALL` |
| 引用的模板变量在必经路径上产出 | 生成的内容永远用不到 | `WORKFLOW_TEMPLATE_UNREACHABLE` |
| 条件键有来源、条件值可枚举 | 分支永远走不到 | `WORKFLOW_CONDITION_*` |

### 3.1 最容易被写错的一条：预算按最长路径算

```python
node_hops, _ = _longest_paths(nodes, order)
if max_nodes < node_hops:
    raise DefinitionError("WORKFLOW_NODE_BUDGET_TOO_SMALL", ...)
```

按**节点总数**算是错的。一张 15 个节点、最长路径 5 的图，配 `max_nodes=8` 完全合理——
分支不会同时走。按总数算会把这种图全判死，用户只能把预算调大，
而预算是防失控的闸门，调大就等于没有。

反过来，如果最长路径都装不下，这张图注定在某条路径上跑到一半停下。那是配错了，
不是运行时意外，应该在保存时就报出来。

### 3.2 第二条：模板必须落在必经路径上

节点 A 引用了 `{{metrics}}`，而 `metrics` 只有节点 B 会产出。
如果 B 在另一条分支上，那么走这条路时 A 拿到的就是空值。

图能跑，不报错，输出里是一个空的 `{{metrics}}` 或者干脆少了那句话。
**这是最典型的「看起来能跑，其实是错的」**，所以要在编译期用必经路径集合判定。

### 3.3 运行时只维护两样东西

编译通过之后，解释器每走一步只更新两个值：**当前游标**和**黑板**。

黑板是一个 `node_id → 输出` 的映射，节点取值时按需从里面读。不维护一个
「全局可变状态对象」，因为那东西一旦被某个节点改了，问题就再也定位不到。

这条约束的收益在续跑。任务中断后重跑，只要游标和黑板还在，就能从断点继续；
如果状态散落在各节点的闭包里，重启之后只能从头跑。

## 4. How：条件值必须可枚举

分支条件最常见的写法是「判断某个变量等于某个值」。这里有一个隐蔽的失败模式：

```python
# 数值比较：float() 失败时静默返回 False
try:
    return float(left) > float(right)
except ValueError:
    return False
```

`emit` 里产出的是「偏高」这种中文字符串，`float("偏高")` 抛异常，函数返回 False。
分支永远不走，也不报错。

两条应对：

1. **`gt` / `lt` 这类数值比较，只对确定是数值的键开放**；
2. **`equals` 这类分支，条件值必须出现在上游节点的 `emit.values` 里**——
   如果节点声明只会输出 `["normal", "high"]`，你配一个 `"critical"`，编译期就报错。

第二条是关键设计：**让配置自己声明值域**，编译器才有东西可校验。
不声明的代价就是所有分支都「可能」，等于没有校验。

## 5. Why：自然语言建图的两个病根

让模型「听一句话生成一张图」很吸引人。做起来的坑不在理解能力，在两件事：

### 病根一：起草即保存

最省事的实现是模型生成 JSON，直接写库。于是用户说一句「帮我建个巡检流程」，
库里立刻多了一张半成品图——而他可能只是想看看长什么样。

正确做法是拆两步：

1. **起草只产草稿，不落库**（放在会话元数据里）；
2. 人看过、说「保存」，才写进 `workflows` 表。

留一个只读的草稿工具，比让用户学会「先删掉再重来」便宜得多。

### 病根二：改一处要重发整张图

用户说「把第三步的 Agent 换成运维」，如果实现是「重新生成整张图」，
那他会发现第一、二、四步也悄悄变了——因为模型每次生成都不完全一样。

所以需要一个 `patch` 能力：只替换指定节点、删除指定节点、改入口。三个动作，够用。

`patch` 有两条铁律：

**第一，它是整节点替换，不是字段合并。** 传什么就是什么，没传的字段等于清空。
字段合并听起来友好，实际会让「删掉一个输入引用」这种操作做不到。

**第二，删掉一个节点导致某步没有后继时，报错，不要自动改接。**
自动改接会让图变得「看起来能跑」，但语义已经错了——
原来的 A→B→C 变成 A→C，中间那步的判断被静默跳过。这种错没人会发现。

## 6. Trade-off：编排的表达力换来了什么

**表达力是受限的。** 没有循环、没有并发分支合并、没有子图嵌套。
只能表达「有向无环 + 条件分支」的流程。

换来的是**可校验**：无环、可达、预算、变量可达性、条件值域，全部能在保存时判定。
一个图灵完备的编排器没法在保存时告诉你「这条路径会死循环」。

**没有「立即运行」接口。** 触发只能走统一入口，因为要走身份解析、限流、审计。
代价是调试时不能一键试跑，得走完整链路。收益是「线上跑的」和「你试的」是同一条路。

**节点预算默认 12，上限 20。** 超过这个规模的流程，问题通常不在预算，
而在流程本身该拆成两个。这个限制是刻意的：它逼着人把流程变小。

## 7. 系列收尾：七篇其实在讲一件事

回头看这七篇，主题各不相同，但反复出现的是同一个判断方式：

| 篇 | 表面在讲 | 实际在讲 |
|---|---|---|
| 1 | 分层 | 代码该放哪，取决于它需要知道什么 |
| 2 | 图的形状 | 路由必须是代码，不能是提示词 |
| 3 | 审批 | 副作用必须幂等，证据必须正向 |
| 4 | 知识库 | 权限必须在内容进入上下文之前生效 |
| 5 | 连接器 | 凭据按租户隔离，缺失即失败 |
| 6 | 网关与观测 | 一个判据、两处使用，才不会有缝 |
| 7 | 编排 | 能编译期校验的，不要留到运行时 |

一句话概括：**把不可靠的东西（模型输出、网络、人的注意力）挡在边界之外，
把必须可靠的东西（权限、幂等、证据、校验）放在边界之内。**

多智能体平台真正的工程量不在「让它会协作」，而在这些边界上。
协作是最容易演示的部分，也是最早做完的部分。

---

## 8. 接下来读什么

如果想动手，建议的顺序是：

1. 先跑通第 2 篇那个七节点图，确认中断恢复真的能跨进程；
2. 加一个只读工具，把网关的判定函数写出来；
3. 加一个写工具和审批单，把四道校验补齐；
4. 再考虑知识库和编排——它们都建立在前三步之上。

反过来做（先上知识库、先做自然语言建图）也能跑出演示，但那套东西在第一次
需要「拦住一个写操作」的时候会全部重写。
